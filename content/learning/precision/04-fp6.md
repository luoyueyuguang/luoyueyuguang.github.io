**fp6（6 位浮点）**。它比 fp8 少 2 个 bit（位宽减 25%，$\frac{6}{8}=0.75$），比 fp4 多 2 个 bit（这不是废话），定位是"用 6 位装下一个神经网络权重"。和 fp8 一样，它由**两个变体**组成：**E3M2** 与 **E2M3**，在精度与范围之间给出两套答案。它目前**没有 IEEE 标准**（注意：OCP 已把它标准化，但 IEEE 754 没有），主要出现在 LLM 权重压缩的研究里。它是 **OCP（Open Compute Project）** 在 2023 年 9 月的 **MX（Microscaling，微缩放）** 规范 v1.0 的成员：规范把 E3M2 / E2M3 两个变体标准化为 **MXFP6**，和 MXFP4 / MXFP8 共享"每 32 个元素一个共享块尺度（E8M0）"的结构（见 OCP MX 规范 v1.0 的 Table 1 与 FP6 元素数据类型 §5.3.2、FP6 编码细节 Table 4）。**硬件上已经不再是零支持**：NVIDIA Blackwell（B200 / GB200 等，第五代 Tensor Core）的 Transformer Engine 原生执行 MXFP6 / MXFP4 / MXFP8 三种格式（见 NVIDIA 2025 年 MXFP8 论文 Table 1）。在 [[learning/precision/01-overview|精度总览]] 中，它属于"低精度 AI 格式"一族，介于 [[learning/precision/05-fp8|FP8]] 与 [[learning/precision/02-nvfp4|NVFP4]] 之间。

> **FP6 用 6 位拿到 fp8 的精度，代价是砍掉指数位、缩小范围。** 它把 fp8 省下的 2 个 bit 几乎全从**指数位**里扣：E2M3 的指数只剩 2 位，却保住了 E4M3 的精度（$u = 0.0625$），但最大只能到 7.5；E3M2 的指数只剩 3 位，保住了 E5M2 的精度（$u = 0.125$），最大到 28。所以 fp6 是**"更窄的 fp8"**：精度不变，范围变小。

### 位布局

fp6 沿用普通浮点"隐式前导 1"的表示，两个变体共享 1 位符号与 6 位总长，区别只在"指数位"和"尾数位"怎么分：

| 字段 | E3M2 | E2M3 |
| --- | --- | --- |
| sign | 1 | 1 |
| exponent | 3（偏置 3） | 2（偏置 1） |
| mantissa（fraction） | 2 | 3 |
| 总计 | 6 | 6 |

普通数的表示和 fp8 同构，只是字段变窄：

$$
x = (-1)^s \cdot 2^{E - \text{bias}} \cdot (1.f)_2
$$

其中 $E$ 是指数字段的值，E3M2 的偏置为 $3$，E2M3 的偏置为 $1$。

```
E3M2:  [s][ E E E ][ M M ]     共 6 位
E2M3:  [s][ E E ][ M M M ]     共 6 位
```

一个具体的例子：E3M2 中 `0 111 10`（符号 0，指数字段 7，尾数位 `10`）对应 $2^{(7-3)} \times (1.10)_2 = 16 \times 1.5 = 24$。而 E2M3 里 `0 11 111`（指数字段 3，尾数位 `111`）对应 $2^{(3-1)} \times (1.111)_2 = 4 \times 1.875 = 7.5$，这正是 E2M3 的最大有限值。

**6 位只有 64 种位模式**（$2^6$）。fp8 有 256 种，其中要留出 inf / NaN 的编码；而 fp6 的两种变体**都没有 inf / NaN**，所以 64 种位模式全部用来表示有限数。每个变体都有 64 个不同的值（含 0），只是这 64 个值在数轴上的分布不同。

### 关键数值

两个变体的"数字性格"差别很大，一张表能看全：

| 指标 | E3M2 | E2M3 |
| --- | --- | --- |
| 有效精度（含隐式前导 1） | 3 bit | 4 bit |
| 单位舍入 $u = 2^{-p}$ | $2^{-3} = 0.125$ | $2^{-4} = 0.0625$ |
| 十进制有效位 | $\approx 3 \log_{10} 2 \approx 0.90$ | $\approx 4 \log_{10} 2 \approx 1.20$ |
| 最大有限值 | $1.75 \times 2^4 = 28$ | $1.875 \times 2^2 = 7.5$ |
| 最小正规数 | $2^{-2} = 0.25$ | $2^{0} = 1.0$ |
| 最小次正规数 | $2^{-2} \times 0.01_{(2)} = 0.0625$ | $2^{0} \times 0.001_{(2)} = 0.125$ |
| 可表示值总数（含 0） | 64 | 64 |
| infinity / NaN | **无** | **无** |

单位舍入 $u$ 是"相对误差下限"。E2M3 的 $u = 0.0625$ 意味着每次四舍五入最多引入约 6% 的相对误差；E3M2 的 $u = 0.125$ 则到约 12%。两者都远超 fp16 的 $2^{-11} \approx 4.9 \times 10^{-4}$，所以 fp6 和 fp8 一样，是"可接受误差 + 更小存储"的格式。

### 和其他格式比一比

把 fp6 的两个变体放回精度谱系，关键是看它们**恰好等于哪一档 fp8 的精度**：

| 格式 | 指数位（偏置） | 尾数位（含隐式） | 单位舍入 $u$ | 十进制有效位 | 最大量级 |
| --- | --- | --- | --- | --- | --- |
| **E3M2** | 3（3） | 3 | $2^{-3} = 0.125$ | ≈0.9 | 28 |
| **E2M3** | 2（1） | 4 | $2^{-4} = 0.0625$ | ≈1.2 | 7.5 |
| fp8（E4M3） | 4（7） | 4 | $2^{-4} = 0.0625$ | ≈1.2 | 448 |
| fp8（E5M2） | 5（15） | 3 | $2^{-3} = 0.125$ | ≈0.9 | $5.7 \times 10^4$ |
| fp16 | 5（15） | 11 | $2^{-11} \approx 4.9\times10^{-4}$ | ≈3.3 | $6.6 \times 10^4$ |

这张表说明：**它保留 fp8 的尾数位，只砍指数位。**

- **E2M3 vs E4M3**：两者的尾数位都是 3（有效精度都是 4 bit，$u = 0.0625$），精度完全一致；E2M3 只是把指数位从 4 砍到 2，范围从 448 缩到 7.5。
- **E3M2 vs E5M2**：两者的尾数位都是 2（有效精度都是 3 bit，$u = 0.125$），精度完全一致；E3M2 只是把指数位从 5 砍到 3，范围从 $5.7\times10^4$ 缩到 28。

所以 fp6 的取舍和 fp8 的 E4M3 / E5M2 是同一对张力，只是压缩得更狠：**省下来的 2 个 bit 全部来自指数位**，换来的是显存 / 带宽减 25%，代价是"动态范围"被压死。

**E3M2 vs E2M3** 的内部取舍也清晰：E3M2 给了更多范围（28 vs 7.5），用精度（0.9 vs 1.2 位十进制）去换；E2M3 给了更多精度，但范围小到只有 $[1.0, 7.5]$ 的正规区间（靠次正规数才延伸到 $0.125$）。和 fp8 的"梯度用 E5M2、前向用 E4M3"类似，两者也是搭档而非竞争。

要想真正理解"fp8 加块共享指数"能带来什么，看 [[learning/precision/06-nvfp8|NVFP8]]；要看 fp6 更近的"更小"邻居，看 [[learning/precision/02-nvfp4|NVFP4]] 与 [[learning/precision/03-mxfp4|MXFP4]]。

### 什么时候需要 / 什么时候不用

fp6 是**研究 / 实验性**格式，判断它是否适用，就是回答"我愿不愿意接受一个没有标准、没有硬件、还要手写 kernel 的格式"。

**可以考虑时：**

- **LLM 权重压缩研究。** fp6 落在 fp8 与 fp4 之间的"还能接受误差"档位：比 fp4 高约一档精度（E2M3 有 4 bit 有效精度 vs fp4 的 2 bit），比 fp8 省 25% 的位宽，是"再压一点"的候选。ZeroQuant(4+2) 与 FP6-LLM 都是围绕 LLM 权重做的。
- **权重动态范围已知且收窄。** 如果逐层量化后，权重的绝对值基本落在某个小区间内（例如都不超过 7），E2M3 会是"精度更高、存储更小"的划算选择。因为这个范围是你校准出来的，不是格式撑起来的。
- **研究低精度格式的误差行为。** 想观察"上溢 / 下溢"在只有指数 2–3 位的格式里如何放大、以及次正规数如何救回小值，fp6 是一个很好的实验台（比 fp8 更容易触发边界）。

**不该用 fp6 时：**

- **通用推理 / 训练（在旧硬件上）。** 没有 IEEE 标准、在 Hopper / Ampere 上也没有 tensor core 支持、软件生态不如 fp8 成熟，在这些平台上软件模拟 MXFP6 往往不如直接 bf16 / fp8 快。**在 Blackwell 上则不同**，MXFP6 是原生路线之一。
- **权重动态范围大。** 一旦某层权重的绝对值可能超过 28（E3M2）或 7.5（E2M3），fp6 只能**饱和**而不是正确地表示。fp8 E4M3 的 448、bf16 的同 fp32 范围都安全得多。
- **需要 inf / NaN 语义。** fp6 两种变体都没有 inf / NaN，溢出只能静默压顶。如果下游想要"宁可报错也不要悄悄错"，fp8 E5M2 或 fp32 更合适。

**取舍的本质**：fp6 用 25% 的位宽节省，换取的是**精度不变 + 范围大幅缩水**。它的好处在"省显存 / 带宽"。别把它当精度提升手段。

### 硬件与软件现状

fp6 的处境正在转变：**数据格式有标准（OCP MX），硬件支持从"无"走向"新代际才有"**。

- **数据格式有开放标准（OCP MX v1.0）**：OCP MX 规范把 E3M2 / E2M3 定义为 **MXFP6** 元素格式（Table 1、§5.3.2、Table 4），和 MXFP4 / MXFP8 是同一个"每 32 元素共享块尺度（E8M0）"的家族。
- **硬件：新一代才有，老一代没有**。NVIDIA **Blackwell（第五代 Tensor Core / Transformer Engine）原生执行 MXFP6、MXFP4、MXFP8**；**Rubin（增强第五代）沿用同样的精度**（NVFP4、FP8/FP6、INT8 等，见 [[learning/precision/06-nvfp8|NVFP8 的硬件现状]]）；但 **Hopper / Ampere 没有**：它们最低只能到 FP8。所以"用 MXFP6"的前提是 Blackwell 及更新代际，老卡上依然要软件模拟。
- **软件生态已在跟进**：NVIDIA **Transformer Engine（TE）** 在 Blackwell 上原生支持 MXFP8 / NVFP4；研究仿真用 Microsoft **microxcaling**（PyTorch/CUDA）可模拟包含 MXFP6 在内的全部 MX 格式。
- **ZeroQuant(4+2)（arXiv:2312.08583）**：提出以 FP6 为中心的 LLM 量化策略，并定义了 E3M2 / E2M3 这两个变体，衡量了把权重压到 6 位的精度效果。
- **FP6-LLM（arXiv:2401.14112）**：为 fp6 手写了一套高性能 GPU kernel，在 Ampere 上把 6 位量化 LLM 的推理吞吐做到接近 fp16 的水平，是 fp6 落地的代表性工作。但它不含块尺度，是"裸 6 位"。
- **打包是不对齐的**：6 bit 不是字节的整数倍，4 个 fp6 值恰好塞进 3 个字节（$4 \times 6 = 24$ bit）。因此 fp6 的实现必须自己做位打包 / 解包，不能像 fp8 那样按字节直接读写。

fp6 在 Blackwell 之前是**研究阶段的格式**；到了 Blackwell（及 OCP 生态），它成了 MX 家族里"介于 fp8 与 fp4 之间"的一员，价值在于"再省 25% 位宽"，但要挑新硬件。

### 代码示例

下面用纯 Python 实现一个简化版 fp6 量化和枚举，展示 E3M2 与 E2M3 的核心差异：**同一个输入，E2M3 在超过 7.5 时饱和，E3M2 能撑到 28**，以及两者在 1.0 附近不同的可表示网格。

```python
# 6-bit fp6 的两种变体：e_bits=指数位, m_bits=尾数位, bias=指数偏置
E3M2 = dict(e_bits=3, m_bits=2, bias=3)   # 1 符号 + 3 指数 + 2 尾数
E2M3 = dict(e_bits=2, m_bits=3, bias=1)   # 1 符号 + 2 指数 + 3 尾数

def fp6_values(e_bits, m_bits, bias):
    """枚举某变体的全部可表示正值：0 + 正规数 + 次正规数。"""
    vals = [0.0]
    for E in range(1, 2 ** e_bits):        # 顶级指数不是 inf/NaN，仍算正规数
        base = 2.0 ** (E - bias)
        for m in range(2 ** m_bits):
            vals.append(base * (1.0 + m / (2 ** m_bits)))
    for m in range(1, 2 ** m_bits):        # E=0 -> 次正规数：2^(1-bias) * m/2^m_bits
        vals.append((2.0 ** (1 - bias)) * (m / (2 ** m_bits)))
    vals.sort()
    return vals

def quantize_fp6(x, e_bits, m_bits, bias):
    """把 x 量化到最近的 fp6 可表示值；无 inf/NaN，超出最大只饱和。"""
    pos = fp6_values(e_bits, m_bits, bias)
    if x == 0:
        return 0.0
    s = -1.0 if x < 0 else 1.0
    a = min(abs(x), pos[-1])               # 饱和到最大值
    q = min(pos, key=lambda v: abs(v - a)) # 最近的可表示值
    return s * q

for x in [0.0, 0.1, 0.4, 1.0, 1.1, 7.0, 20.0, 100.0]:
    print(f"{x:>7} -> E3M2={quantize_fp6(x, **E3M2):>8}; E2M3={quantize_fp6(x, **E2M3):>8}")

print("E3M2 可表示正值个数:", len(fp6_values(**E3M2)), "最大:", fp6_values(**E3M2)[-1])
print("E2M3 可表示正值个数:", len(fp6_values(**E2M3)), "最大:", fp6_values(**E2M3)[-1])
print("E3M2 1.0 附近:", [v for v in fp6_values(**E3M2) if 0.8 <= v <= 1.4])
print("E2M3 1.0 附近:", [v for v in fp6_values(**E2M3) if 0.8 <= v <= 1.4])
```

输出要点：

```text
    0.0 -> E3M2=     0.0; E2M3=     0.0
    0.1 -> E3M2=   0.125; E2M3=   0.125
    0.4 -> E3M2=   0.375; E2M3=   0.375
    1.0 -> E3M2=     1.0; E2M3=     1.0
    1.1 -> E3M2=     1.0; E2M3=   1.125
    7.0 -> E3M2=     7.0; E2M3=     7.0
   20.0 -> E3M2=    20.0; E2M3=     7.5
  100.0 -> E3M2=    28.0; E2M3=     7.5
E3M2 可表示正值个数: 32 最大: 28.0
E2M3 可表示正值个数: 32 最大: 7.5
E3M2 1.0 附近: [0.875, 1.0, 1.25]
E2M3 1.0 附近: [0.875, 1.0, 1.125, 1.25, 1.375]
```

可以看到：`1.1` 对 E3M2 来说落到 `1.0`（它在此区间只有 0.875 / 1.0 / 1.25 三个网格点），而 E2M3 能给出更近的 `1.125`，说明 E2M3 的精度高了半档。当数值涨到 `20` 时，E2M3 已经**超过最大有限值 7.5**，于是饱和到 7.5；E3M2 还能装下 `20`，直到 `100` 才饱和到 28。两者都是"无 inf/NaN，压顶"的性格。

每个变体各有 32 个正值（含 0、正规数、次正规数），配上符号位正好是 64 种位模式：6 个 bit 全部用满，没有浪费。

### 一些 tips

1. **fp6 是"精度不变、范围缩小"的 fp8。** E2M3 ≈ E4M3 的精度、E3M2 ≈ E5M2 的精度，省下的 2 bit 全在指数位。好处是省 25% 的显存 / 带宽。别把它当精度提升手段。
2. **E2M3 和 E3M2 不能混用。** 二者偏置、网格都不同，不能直接相加或比较；混用前必须各自解回 fp32，再做混合精度的更新。选哪个取决于你更怕"精度不够"（选 E2M3）还是更怕"撑不下范围"（选 E3M2）。
3. **留意饱和而非溢出。** fp6 两种变体都没有 inf / NaN，超范围只会静默压顶到最大有限值（28 或 7.5）。量化前要确认权重范围，否则一个偏大的层会悄悄损失大量信息。
4. **必须打包 / 解包。** 6 bit 不是字节的整数倍，4 个值塞进 3 个字节；写 kernel 时这往往比数值计算本身更繁琐，也是最容易出错的地方。
5. **"无标准 / 无硬件"都要分代际说。** 数据格式有 OCP MX 标准（MXFP6）；硬件执行在 **Blackwell 已原生支持**，但在 **Hopper / Ampere 上仍是零**。价值从"验证 6 位还可不可用"转变为"在 Blackwell 上再省 25% 位宽的候选"。真要落地，确认硬件是否支持 MXFP6 优先于看 fp8。
