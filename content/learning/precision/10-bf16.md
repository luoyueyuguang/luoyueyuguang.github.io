聊 AI 精度格式，**bfloat16（brain floating point，简写 bf16，即"大脑浮点"）**是绕不开的主角。它由 Google Brain 提出（约 2018 年前后，最初为 TPU v2 设计），思路是：**把 fp32 的 23 位尾数砍到只剩 7 位，却完整保留 fp32 的 8 位指数**。于是它用一半的存储换来了和 fp32 一模一样的数值范围，代价只是精度从约 7 位十进制掉到约 2.4 位。它是"要省钱、又怕范围不够"时的默认答案。

> bf16 是 fp16 和 fp32 的"中间态"：它占 16 位（和 fp16 一样省），但指数范围完全等于 fp32，所以**几乎不会溢出或下溢**（范围与 fp32 同宽，只是拖到 $2^{-133}$ 以下的次正规区才真正下溢），只是精度只有约 2.4 位十进制。它把 fp16"精度高但范围太小"的老毛病治好了，代价是精度比 fp16 还差一档。这是今天大模型混合精度训练几乎默认用它做权重/激活存储的原因。

### 位布局

bfloat16 本质是 fp32（binary32）的"高 16 位截断版"：符号位和指数位原样保留，尾数从 23 位砍到 7 位。

| 字段 | 位数 |
| --- | --- |
| sign | 1 |
| exponent | 8（偏置 127） |
| fraction | 7 |
| 总计 | 16 |

```
 15    14                   7            0
 ┌─────┬───────────────────┬──────────────┐
 │  s  │   exponent (8)    │  fraction(7) │
 └─────┴───────────────────┴──────────────┘
```

普通数（正规数，normal）的表示与 fp32 完全同构，只是尾数变窄：

$$
x = (-1)^s \cdot 2^{E - 127} \cdot (1.f)_2
$$

- 指数偏置为 **127**，和 fp32 的 8 位指数完全一致，这是"范围等于 fp32"的根源。
- 指数域 $E=0$（次正规/零）与 $E=255$（±∞/NaN）为特殊值。次正规数：
  $$
  x = (-1)^s \cdot 2^{-126} \cdot (0.f)_2
  $$
- 从 fp32 转 bf16 只需一步：**取 fp32 的高 16 位（符号 + 指数 + 尾数高 7 位）**，对低 16 位做舍入（round-to-nearest-even 或直接截断）。因为指数位不用动，转换几乎零成本。

由于它的指数域和 fp32 一模一样，**bf16 的最小正规数是 $2^{-126} \approx 1.18 \times 10^{-38}$**，次正规最小到 $2^{-133} \approx 9.2 \times 10^{-41}$，和 fp32 相同，只是小数部分的精度被砍掉了。

### 关键数值

| 项目 | bfloat16 |
| --- | --- |
| 有效精度（significand，含隐式前导 1） | 8 bit |
| 单位舍入 $u$ | $2^{-8} = 1/256 \approx 3.91 \times 10^{-3}$ |
| 十进制有效位 | $8 \log_{10} 2 \approx 2.4$ |
| 最大正规数 | $(2^7+2^7-1)/2^7 \cdot 2^{127} \approx 3.39 \times 10^{38}$ |
| 最小正规数 | $2^{-126} \approx 1.18 \times 10^{-38}$ |
| 次正规最小值 | $2^{-133} \approx 9.2 \times 10^{-41}$ |
| 指数偏置 | 127 |

$u \approx 3.9 \times 10^{-3}$ 意味着任何数在 bf16 里只能保留约 **3 位十进制有效数字**，和"计算器上输入 3.14159 但只记得 3.14"差不多。而范围却一路拉到 $10^{38}$，连 $10^{-38}$ 的极小量都放得下，**这就是"拿精度换范围"**。

### 和邻近格式比

| 格式 | 指数位 | 尾数位（含隐式） | 单位舍入 $u$ | 十进制有效位 | 最大量级 | 最小正规数 |
| --- | --- | --- | --- | --- | --- | --- |
| fp16 | 5 | 11 | $2^{-11} \approx 4.9\times10^{-4}$ | ≈3.3 | 65504 | $6.10\times10^{-5}$ |
| **bfloat16** | **8** | **8** | $2^{-8} \approx 3.9\times10^{-3}$ | **≈2.4** | **$3.39\times10^{38}$** | **$1.18\times10^{-38}$** |
| fp32 | 8 | 24 | $2^{-24} \approx 6.0\times10^{-8}$ | ≈7.2 | $3.40\times10^{38}$ | $1.18\times10^{-38}$ |

对比 [[learning/precision/09-fp16|fp16]] 和 [[learning/precision/12-fp32|fp32]] 就能看清 bf16 的定位：

- **vs fp16**：两者都占 16 bit，但 fp16 尾数更宽（11 vs 8），精度略好（≈3.3 vs ≈2.4 位十进制）；可惜 fp16 只有 5 位指数，最大值只有 65504，最小值正规数也只有 $6.1\times10^{-5}$，一个 $10^{-4}$ 左右的梯度就会下溢成 0。**bf16 把这层顾虑完全抹掉**：范围和 fp32 一样，小梯度、大激活都不怕。
- **vs fp32**：范围完全一样（指数位相同），但精度从 24 位砍到 8 位。所以 bf16 是"**fp32 的范围 + 低配精度**"。
- **vs fp8**：更往下的 [[learning/precision/05-fp8|fp8]] 把指数和尾数一起砍，范围、精度都进一步缩水，是"还要更省"时的下一步。

> **fp16 精度最高但范围最窄，bf16 范围最大但精度最低，fp32 两者都最强但最贵。**

### 什么时候需要它

判断标准就一条：**你的数值会不会踩到 fp16 的范围边界**，同时又想省一半存储/带宽。

1. **大模型混合精度训练（如今的默认）**。训练里激活值、梯度、权重动辄跨多个数量级。fp16 的 65504 上限和 $6\times10^{-5}$ 下限让大梯度容易溢出、小梯度容易下溢，为此通常要引入 **loss scaling**（把梯度人为放大再缩回）。bf16 因为指数位和 fp32 相同，**不需要 loss scaling**，训练循环更简单、更稳。主流训练栈（PyTorch 的 `torch.autocast("bfloat16")`、TensorFlow 的 mixed precision、transformers 生态）都把 bf16 作为大模型的默认混合精度类型。

2. **推理/微调时的权重与激活存储**。半精度的存储和带宽成本是 fp32 的一半，bf16 在"怕溢出"的场景下比 fp16 更安全，所以很多 LLM 推理框架（vLLM、TensorRT-LLM 等）的默认 dtype 是 bf16。

3. **范围跨度大的科学计算加速**。只要容忍约 2.4 位有效数字，bf16 能给那些"量级飞跃、不需精算"的近似问题提速（例如数值积分的粗略扫描、模拟中的粗筛）。

### 什么时候不用它

1. **需要精确累加或高精度收敛**。8 位有效数字意味着累加/点积误差很快被放大；bf16 只适合做"乘法-存储"，**累加必须放在 fp32 或更高精度**。纯 bf16 的归约（如 large-N 求和）结果会明显偏离。

2. **需要保留 4 位以上有效数字**。做几何计算、坐标转换、精确的插值/求根时，2.4 位十进制远远不够，得上 [[learning/precision/12-fp32|fp32]] 或更高。

3. **数值本身在 1 附近且要求绝对精度**。bf16 对 1.0 附近的数只能分辨到约 0.004 的间隔：`1.0` 和 `1.001` 在 bf16 里是同一个数。凡是需要"几个小数位"的应用都不行。

4. **整数/精确计数类**。bf16 和 fp16 一样不适合整数运算；离散、计数场景请用 [[learning/precision/08-int8|int8]] 或整型。

5. **需要跨硬件可复现的严格比较**。不同设备上 bf16 的舍入策略、中间累加精度可能略有差异，作严格基准时要小心。

### 硬件与软件现状

bf16 是**存储格式，也是计算格式**。和纯存储的某些自定义格式不同，它在主流硬件上有真正的运算支持：

- **NVIDIA GPU**：Ampere（A100，2020）起 Tensor Core 原生支持 bf16，吞吐与 fp16 相当（A100 约 312 TFLOPS 稠密 / 624 TFLOPS 稀疏），Hopper（H100）进一步翻数倍。CUDA 提供 `__nv_bfloat16` / `__nv_bfloat162` 类型及 `bf16` 转换内建。
- **Google TPU**：bf16 的"老家"，TPU v2/v3/v4 张量核心的默认运算精度，混合精度训练中 bf16 + fp32 累加是标准配置。
- **Intel / AMD CPU**：Intel Xeon（AVX-512 BF16 扩展）、AMD Zen / Instinct 都支持；库层面有 oneAPI MKL、AMD 优化库。
- **ARM**：ARMv8.6-A 引入 bf16 指令；Apple 的 A15/M2 及后续芯片（Neural Engine）支持。
- **其他加速器**：AWS Inferentia / Trainium、Intel 数据中心 GPU 等均已支持。
- **框架**：PyTorch（`torch.bfloat16`）、TensorFlow（`tf.bfloat16`）、CUDA、ROCm、JAX 等全面支持。

注意区分：bf16 是**真正的运算格式**（硬件直接算），和"只在存储时用、计算前要转回 fp32"的纯存储格式不一样。但它依然常和 fp32 混合：**计算时用 fp32 累加、bf16 只做乘法/存储**，这是混合精度的精髓。

### 代码示例

下面这段**纯 Python** 实现把任意 fp32 值舍入到最近的 bfloat16（round-to-nearest-even），不依赖任何第三方库。它直观展示 bf16 的"两大性格"：

```python
import struct

def to_bf16(x: float) -> float:
    """把 fp32 值舍入到最近的 bfloat16（仍以 Python float 返回）。

    原理：bfloat16 = 取 fp32 的高 16 位（sign + 8 位指数 + 尾数高 7 位），
    对要丢弃的低 16 位做 round-to-nearest-even。
    """
    if x != x or x in (float("inf"), float("-inf")):
        return x
    b = struct.unpack(">I", struct.pack(">f", x))[0]  # 取 fp32 的 32 bit
    top = b >> 16      # sign + exp + 尾数高 7 位
    low = b & 0xFFFF   # 即将丢弃的低 16 位
    # round-to-nearest-even
    if low > 0x8000 or (low == 0x8000 and (top & 1)):
        top += 1
    if (top & 0x7F80) == 0x7F80:          # 指数全 1 -> 溢出成无穷
        return float("inf") if x >= 0 else float("-inf")
    return struct.unpack(">f", struct.pack(">I", top << 16))[0]

u = 2.0 ** -8
print(f"单位舍入 u = 2^-8 = {u:g} (= {u:.4e})")

for v in [1.0, 1.001, 3.14159265, 65536.0, 1e30, 1e-20, 3.39e38]:
    print(f"{v:16.8g}  ->  bf16 {to_bf16(v):16.8g}")
```

运行输出（关键点）：

```
             1  ->  bf16                1
           1.001  ->  bf16                1
       3.1415927  ->  bf16         3.140625
           65536  ->  bf16            65536
           1e+30  ->  bf16    1.0002556e+30
           1e-20  ->  bf16    1.0005577e-20
        3.39e+38  ->  bf16    3.3895314e+38
```

能看到两件事：

- **精度**：`1.001` 舍入后变回 `1.0`（最近可表示的是 1.0 和 1.0078125，1.001 更靠近 1.0）；π 变成 3.140625，只有约 3 位有效数字。
- **范围**：`1e30`、`1e-20` 甚至接近上限的 `3.39e38` 全都**正常保号、无溢出**。换成 [[learning/precision/09-fp16|fp16]]，`1e-20` 在最小正规数（$6.1\times10^{-5}$）之下早就下溢成 0 了，而 bf16 完全不慌，这正是它值钱的地方。

在真实框架里，直接用 `torch.bfloat16` 即可：

```python
import torch
w = torch.randn(4096, 4096, dtype=torch.bfloat16)   # 权重/激活用 bf16 存
x = w.float() @ w.float()                            # 累加用 fp32，避免精度堆积
print(x.dtype)                                       # torch.float32
```

### 一些tips

1. **bf16 ≠ 小号 fp16**。它俩唯一的共同点是"都是 16 位"。bf16 的范围是 fp32 等级，精度却低于 fp16；选哪个要看你的痛点是"溢出/下溢"还是"精度不足"。
2. **累加永远用 fp32**。bf16 只有 8 位有效数字，归约（sum、dot、softmax 的求和部分）要在 fp32 里做，混合精度的好处才成立。纯 bf16 累加是大数吃小数，误差会随长度膨胀。
3. **必要时才上 loss scaling**。大多数框架在 bf16 下默认不需要 loss scaling（范围够大）；如果仍遇到 NaN/Inf，先检查是否有极端激活值或梯度爆炸，而不是先加 scaling。
4. **转换方向要留意舍入**。fp32 → bf16 时 direct truncation（round toward 0）和 round-to-nearest-even 结果会差一个 ulp；对精度敏感时用 round-to-nearest。
5. **别把 bf16 当 fp32 的替身**。只要你的计算需要超过 ~3 位有效数位（几何、精确求根、严格收敛），就得回 [[learning/precision/12-fp32|fp32]] 或更高（[[learning/precision/13-fp64|fp64]] / [[learning/precision/15-fp128|fp128]]）。
6. **"累加用 fp32"在较新架构上要主动确认**。BF16 GEMM 默认会开 reduced precision reduction（把中间累加也截回 bf16，可能因此冒出 `inf`）；要真 fp32 累加，用 `torch.backends.cuda.matmul.allow_bf16_reduced_precision_reduction = False` 关闭。
