## FP8：E4M3 与 E5M2

聊精度，大部分人第一反应是 fp16 / bf16 / fp8。前两个是"16 位"的主流派，而 **fp8** 是这条谱系里最激进、也最接地气的入口：它只用 8 位（一个字节）去装一个神经网络权重，却通过**两种变体**——**E4M3** 和 **E5M2**——在精度与范围之间给出了两套答案。它是当前 70B 级大模型推理与混合精度训练的"主力低精度格式"，也是 OCP 的微缩放（Microscaling）系列与 NVIDIA 张量核心共同依赖的底层，在 [[learning/precision|精度总览]] 里属于"低精度 AI 格式"一族。

一句话给直觉：

> **FP8 用 1 个字节装下一个网络权重，但要靠"两块互相妥协"的变体分工。E4M3（4 位指数 + 3 位尾数）偏向精度与稳定，最大只能到 448；E5M2（5 位指数 + 2 位尾数）把范围放大到 57344，代价是有效数字更少。两者都只是"把 fp32 的 23 位尾数砍到 2–3 位"，真正的误差缓冲来自统一的 fp32 累加。**

### 位布局

FP8 是 OCP（Open Compute Project）定义的标准 8 位浮点，两种变体共享 1 位符号与 8 位总长，区别只在"指数位"和"尾数位"怎么分：

| 字段 | E4M3 | E5M2 |
| --- | --- | --- |
| sign | 1 | 1 |
| exponent | 4（偏置 7） | 5（偏置 15） |
| mantissa（fraction） | 3 | 2 |
| 总计 | 8 | 8 |

两种变体都沿用了普通浮点"隐式前导 1"的表示：

$$
x = (-1)^s \cdot 2^{E - \text{bias}} \cdot (1.f)_2
$$

其中 $E$ 是指数字段的值，E4M3 的偏置为 $7$，E5M2 的偏置为 $15$。

```
E4M3:  [s][ E E E E ][ M M M ]   共 8 位
E5M2:  [s][ E E E E E ][ M M ]   共 8 位
```

一个具体的例子：E4M3 中 `0 1111 110`（符号 0，指数字段 15，尾数位 `110`）对应 $2^{(15-7)} \times (1.110)_2 = 256 \times 1.75 = 448$。这正是 E4M3 的最大有限值。

### 关键数值

两者的"数字性格"差别很大，一张表能看全：

| 指标 | E4M3 | E5M2 |
| --- | --- | --- |
| 有效精度（含隐式前导 1） | 4 bit | 3 bit |
| 单位舍入 $u = 2^{-p}$ | $2^{-4} = 0.0625$ | $2^{-3} = 0.125$ |
| 十进制有效位 | $\approx 4 \log_{10} 2 \approx 1.2$ | $\approx 3 \log_{10} 2 \approx 0.9$ |
| 最大有限值 | $448$ | $57344$ |
| 最小正规数 | $2^{-6} \approx 0.015625$ | $2^{-14} \approx 6.10 \times 10^{-5}$ |
| 最小次正规数 | $2^{-9} \approx 0.001953$ | $2^{-16} \approx 1.53 \times 10^{-5}$ |
| infinity | **无**（仅 NaN） | **有** |

单位舍入 $u$ 是"相对误差下限"。E4M3 的 $u = 0.0625$ 意味着任何一次四舍五入最多引入约 6% 的相对误差；E5M2 更是只有约 12%。**这已经远超"肉眼看不出来"的程度**，所以 FP8 从来不是"精确"的格式，而是"可接受误差 + 巨大吞吐"的格式。

### 和其他格式比一比

把 FP8 放回精度谱系里，它的"小"和"窄"一目了然：

| 格式 | 指数位（偏置） | 尾数位（含隐式） | 单位舍入 $u$ | 十进制有效位 | 最大量级 |
| --- | --- | --- | --- | --- | --- |
| **E4M3** | 4（7） | 4 | $2^{-4} = 0.0625$ | ≈1.2 | 448 |
| **E5M2** | 5（15） | 3 | $2^{-3} = 0.125$ | ≈0.9 | $5.7 \times 10^4$ |
| fp16 | 5（15） | 11 | $2^{-11} \approx 4.9\times10^{-4}$ | ≈3.3 | $6.6 \times 10^4$ |
| bf16 | 8（127） | 8 | $2^{-8} \approx 3.9\times10^{-3}$ | ≈2.4 | $3.4 \times 10^{38}$ |
| fp32 | 8（127） | 24 | $2^{-24} \approx 6.0\times10^{-8}$ | ≈7.2 | $3.4 \times 10^{38}$ |

注意一个反直觉的点：**fp16 和 E5M2 的最大量级几乎一样**（$6.6\times10^4$ 和 $5.7\times10^4$），但 fp16 用 11 位尾数换来了 3 位十进制有效数字，而 E5M2 只有 0.9 位——两者在"精度 vs 范围"这条轴上站在不同的平衡点上。E4M3 则是把精度位稍微多给一点、把范围压死。

要想真正理解"给 FP8 加一块共享指数"能带来什么，看 [[learning/precision/mxfp8|MXFP8]]；要看 NVIDIA 在张量核心上具体怎么落地，看 [[learning/precision/nvfp8|NVFP8]]；要比较"范围但精度更低"的另一种选择，看 [[learning/precision/bf16|BF16]]。

### 什么时候需要 / 什么时候不用

FP8 的黄金原则是**分工**：两种变体本来就不是竞争关系，而是搭档。

**需要 E4M3（精度 + 无 infinity）时：**

- **推理的权重与激活**（W8A8）。前向传播的数值范围相对可控，激活值通常落在几十以内，E4M3 覆盖不到 448 之外；它没有 infinity，即使某个激活暴涨也只会**饱和到 ±448**，不会产生 inf/NaN 污染整个计算，这让推理更稳。
- **混合精度训练的前向**。权重、激活、绝大多数中间结果都远小于 448，E4M3 的有效精度（4 bit）比 E5M2（3 bit）高一档，前向能多保住一点信息。

**需要 E5M2（宽范围）时：**

- **梯度（反向传播）**。梯度是训练里"最没谱"的数值：既可能极小（接近下溢）也可能很大（濒临上溢）。E5M2 的指数位多 1 位，把范围拉到 $\pm 57344$，次正规数也能到 $2^{-16}$，能兜住梯度的动态范围。而且它**有 infinity**，溢出时正确地变成 inf 而不是悄悄饱和成一个错的 57344——训练者宁可看到 inf 报错，也不愿看到一个"假梯度"。
- 需要覆盖**跨多个数量级**的数值、且不介意精度更低时。

**不该用 FP8 时：**

- 需要超过约 1–2 位十进制有效数字的任务——FP8 的误差是百分之几量级，任何对精度敏感的量（例如归一化统计量、softmax 输入的 logits、跨层长时间累加）都不适合 8 位。
- 激活值可能有 $>448$ 的绝对值、且不能接受饱和/inf 时——此时应保留 bf16（范围与 fp32 相同）或 fp32。
- 硬件不支持 FP8 张量核心时，用软件模拟 FP8 得不偿失，直接 bf16/fp32 更快。

**取舍的本质**：FP8 用 8 位同时换了**显存减半**（相对 fp16/bf16 是减半）和**张量核吞吐翻倍**，但代价是精度掉到 1 位十进制左右。真正让它"能用"的不是格式本身，而是**乘加累加发生在 fp32**——8 位只"输入"，32 位只"累计"，两者配合把误差压在一个可控范围内。

### 硬件与软件现状

FP8 的普及**几乎全靠 GPU 硬件**，这是它和 fp128（几乎没有硬件）形成鲜明对比的原因。

- **NVIDIA**：从 **Hopper**（H100 / H200）开始，Tensor Core 原生支持 FP8（E4M3 与 E5M2）矩阵乘法；**Ada**（L40S、RTX 40 系）和 **Blackwell**（B200、GB200、RTX 50 系）继续沿用并增强。FP8 计算时**累加固定发生在 fp32**。
- **AMD**：Instinct MI300 系列（MI300X 等）在新一代 Instinct 加速器上提供 FP8 张量运算。
- **Intel**：Gaudi 加速器（Gaudi 2 / Gaudi 3）原生支持 FP8，面向数据中心的 Xeon 系列也在新一代中加入低精度矩阵运算优化。
- **软件栈**：PyTorch 提供 `torch.float8_e4m3fn`（`fn` 指 finite，无 infinity）和 `torch.float8_e5m2` 两种 dtype；NVIDIA **Transformer Engine** 用 FP8 封装了 H100 训练路径（自动缩放）；inference 侧 **vLLM / SGLang / TensorRT-LLM** 把 FP8 作为 W8A8 量化的主流选项；Triton、DeepSpeed（`fp8` 混合精度）也都支持。

**存储格式 vs 纯计算格式**要区分清楚：

- FP8 既是**存储格式**——一个权重/激活只占 1 字节，显存和带宽减半；也是**计算输入格式**——张量核心直接读 FP8 做乘，但**累加在 fp32**。
- 相比之下，[[learning/precision/tf32|TF32]] 是"纯计算格式"：它只在张量核心内部存在，没有对应的存储 dtype，你无法把一个普通数组声明成 tf32。FP8 不一样，它有真实的 dtype 和位布局，能被存盘、被反序列化、被量化工具读取。

### 代码示例

下面用纯 Python 实现一个简化版 FP8 量化/解量化，展示 E4M3 与 E5M2 的核心差异：**同样的输入，E4M3 饱和到 ±448，E5M2 溢出到 ±inf**，以及两者在 1.0 附近的可表示网格。

```python
import math

# OCP FP8 两种变体
# E4M3: 1 符号 + 4 指数(bias 7) + 3 尾数；无 infinity，溢出饱和到 ±448
# E5M2: 1 符号 + 5 指数(bias 15) + 2 尾数；有 infinity，溢出到 ±inf

def quantize(x, man_bits, max_finite, saturate):
    """把 x 量化到某个 FP8 格式的可表示网格，并处理上溢。"""
    if x == 0:
        return 0.0
    sign = -1.0 if x < 0 else 1.0
    a = abs(x)
    if a > max_finite:                 # 上溢：两种格式的处理方式完全不同
        return sign * max_finite if saturate else math.inf * sign
    e = math.floor(math.log2(a))       # 当前数量级
    grid = 2.0 ** (e - man_bits)       # 该指数下可表示值的间隔
    q = round(a / grid) * grid         # 四舍五入到最近网格点
    return sign * min(q, max_finite)

E4M3 = dict(man_bits=3, max_finite=448.0,     saturate=True)    # 无 infinity
E5M2 = dict(man_bits=2, max_finite=57344.0,   saturate=False)   # 有 infinity

for x in [1.06, 2.1, 100.0, 1000.0, 3e6]:
    print(f"{x:>9} -> E4M3={quantize(x, **E4M3):>10}; E5M2={quantize(x, **E5M2):>10}")

# x=1 附近的可表示网格（相邻值之差就是 2*u）
print("E4M3 near 1.0:", quantize(1.0, **E4M3), quantize(1.125, **E4M3))
print("E5M2 near 1.0:", quantize(1.0, **E5M2), quantize(1.25,  **E5M2))

# 边界值
print("E4M3 max / min-normal:", 448.0, 2.0 ** -6)
print("E5M2 max / min-normal:", 57344.0, 2.0 ** -14)
```

输出要点：

```text
    1.06 -> E4M3=       1.0; E5M2=       1.0
     2.1 -> E4M3=       2.0; E5M2=       2.0
   100.0 -> E4M3=      96.0; E5M2=      96.0
  1000.0 -> E4M3=     448.0; E5M2=    1024.0
3000000.0 -> E4M3=     448.0; E5M2=       inf
E4M3 near 1.0: 1.0 1.125
E5M2 near 1.0: 1.0 1.25
```

可以看到：`1000` 对 E4M3 来说已经**超出最大有限值 448**，于是被饱和到 448；而 E5M2 能装下 `1000`（量化成最近的网格点 1024）。当数值涨到 `3×10^6` 时，E4M3 仍是 448（无 infinity，压顶），E5M2 则正确地溢出为 `inf`。这个差别是"训练时用 E5M2 更安全"的直接原因。

### 一些 tips

1. **E4M3 没有 infinity，只会"压顶"**。超范围时 E4M3 饱和到 $\pm 448$，不会产生 inf/NaN 去污染下游；E5M2 会正确地溢出成 inf。别把两者当可互换——选哪个取决于你更怕"悄悄错"还是更怕"爆掉"。
2. **必须 fp32 累加**。FP8 的乘加如果也在 FP8 里累加，误差会以 $\sim N \cdot u$ 的速率累积到爆表；所有支持 FP8 的硬件都强制**乘用 FP8、累加在 fp32**。你在软件里也应沿用这一分工。
3. **留意缩放因子（scale）**。FP8 是"相对误差固定"的格式，绝对误差和动态范围靠**每个张量/每层一个 scale 因子**撑起来。scale 选小了会下溢、选大了会浪费有效位数，实际工程里通常用校准数据或动态调度来定（Transformer Engine 的自动缩放就是这个思路）。
4. **别拿 FP8 当"精度不是问题"**。1–2 位十进制有效数字，对归一化统计量、softmax 输入、跨层累加这类敏感值是灾难；这些量通常保留 fp32，只有"大头"的权重和主激活走 FP8。
5. **E4M3 与 E5M2 混用的正确姿势**。前向用 E4M3、反向梯度用 E5M2 是常见组合，但两者**不能直接相加**——它们的 bias 和网格都不同，必须各自带 scale，换算成 fp32 后再做混合精度的更新。
