# MXFP4：OCP 微缩放 FP4

聊到 4 bit 精度，大家第一反应通常是"4 bit 能表示什么？"。但对 AI 来说，更关键的是**一整条权重向量怎么用一个共同的尺度去缩放**。MXFP4 就是这个思路的产物：它是 OCP（Open Compute Project）在 2023 年发布、由 AMD / Arm / Intel / Meta / Microsoft / NVIDIA / Qualcomm 联合制定的**微缩放（Microscaling，MX）**格式家族的一员：每 32 个 4 bit 元素共享一个 8 bit 的块尺度。

> MXFP4 是**每 32 个元素配一个指数**。它把"谁负责缩放"从"整个张量"细化到"32 个数的块"，于是权重幅值在块与块之间差很多时也能被精确表示，而付出的代价只有每元素 0.25 bit 的尺度开销。它解决的是**标量 FP4 在权重幅值剧烈变化时的"表示真空"**：太小的小数被压成 0，太大的被削顶，而 MX 的块尺度让每一块都"各取所需"。

相关：[[learning/precision/02-nvfp4|NVIDIA FP4]]（标量/每通道尺度）、[[learning/precision/07-mxfp8|MXFP8]]（同一块尺度方案，8 bit 元素）、[[learning/precision/01-overview|精度总览]]。

### 位布局

一个 MX 块由**一个共享尺度 $X$** + **$k=32$ 个元素 $P_i$** 组成。尺度与元素的数据类型独立选择，布局在物理内存中不强制：尺度可以和元素连续存放，也可以分开存（见 OCP MX 规范 §5.1）。

```
  块尺度 X（E8M0，8 bit）          32 个元素 P_i（E2M1，每 4 bit）
  +-----------+          +---+---+---+---+      +---+---+---+---+
  |  exponent |          | s | E | M |  ...    | s | E | M |
  +-----------+          +---+---+---+---+      +---+---+---+---+
  bias = 127                1   2   1  bit/元素     1   2   1
```

存储一个块需要 $w + kd = 8 + 32 \times 4 = 136$ bit，平均每个元素 $136/32 = 4.25$ bit，比裸的 4 bit 只多了 $8/32 = 0.25$ bit 的"管理费"。

**块尺度 $X$：E8M0。** 一个**无符号的、带偏置的 Float32 指数**，没有符号、没有尾数，bias = 127：

$$
X = 2^{E - 127}
$$

$E$ 是 8 bit 无符号值，合法范围 $E = 0 \ldots 254$，对应指数 $-127 \sim 127$（$E=255$ 被保留为唯一的 NaN 编码 $11111111_2$）。注意 E8M0 **不含 Inf**：它只能描述一块的"量级"，不能描述无穷。关键点是：**E8M0 本身不贡献精度，只贡献范围**。它的指数范围覆盖了 Float32 的指数范围（$-126 \sim 127$），甚至更宽一点，所以一整块乘法永远不会因为尺度溢出。

**元素 $P_i$：E2M1。** 1 bit 符号 + 2 bit 指数 + 1 bit 尾数，bias = 1。和 IEEE 一样分规范数（normal）与非规范数（subnormal），但**不保留任何 Inf / NaN 编码**（所有 16 种编码都是有限值）：

$$
P = (-1)^S \cdot 2^{E-1} \cdot (1.M)_2 \quad (E > 0, \text{normal})
$$

$$
P = (-1)^S \cdot 2^{0} \cdot (0.M)_2 \quad (E = 0, \text{subnormal})
$$

因为 $M$ 只有 1 bit，$M \in \{0,1\}$，所以 $0.M$ 只可能是 $0$ 或 $0.5$。于是 E2M1 的**可表示幅值**是一个很小的集合（先忽略符号、再乘以 $X$）：

| 指数字段 $E$ | 指数 $E-1$ | 幅值 $M=0$ | 幅值 $M=1$ | 类型 |
| --- | --- | --- | --- | --- |
| `00` | —（subnorm） | $0$ | $0.5$ | 0 / 次正规 |
| `01` | $0$ | $1.0$ | $1.5$ | 规范数 |
| `10` | $1$ | $2.0$ | $3.0$ | 规范数 |
| `11` | $2$ | $4.0$ | $6.0$ | 规范数（最大） |

整个块的值是 $v_i = X \cdot P_i$（若 $X$ 为 NaN，则整块都为 NaN；若 $|XP_i| > V_{\max}^{Float32}$，行为由实现决定）。

### 关键数值

| 参数 | 值 |
| --- | --- |
| 元素格式 | E2M1（1 符号 + 2 指数 + 1 尾数） |
| 元素有效精度 $p$ | **2 bit**（1 隐式前导 + 1 显式尾数） |
| 元素单位舍入 $u = 2^{-p}$ | $2^{-2} = 0.25$（**25% 相对误差**！） |
| 十进制有效位数 | $\approx 2\log_{10}2 \approx 0.60$ 位 |
| 元素最大幅值（归一化） | $6.0$ |
| 元素最小非零（归一化） | $0.5$（次正规） |
| 块内动态范围（最大/最小非零） | $6.0 / 0.5 = 12$（约 1.08 个数量级） |
| 块尺度格式 | E8M0（8 bit 带偏置指数，bias 127） |
| 尺度覆盖范围 | $2^{-127} \sim 2^{127}$ |
| 块大小 $k$ | $32$ |
| 每块位数 | $8 + 32 \times 4 = 136$ bit |
| 平均每元素位宽 | $4.25$ bit |
| 尺度开销 | $8/32 = 0.25$ bit/元素 |

两个数字要特别理解：

- **$u = 25\%$** 是 E2M1 的本质：尾数只有 1 bit，规范数只能落在 ${1.0, 1.5, 2.0, 3.0, 4.0, 6.0}$ 这些网点上，相邻网点最多差 50%（$1.5$ 到 $2.0$ 差 33%，$3.0$ 到 $4.0$ 差 33%）。所以 MXFP4 的单元素精度只有约 0.6 位十进制，是很糙的网格。
- **$u$ 是"相对"误差**，而且**尺度 $X$ 是 2 的幂，本身无误差**。也就是说，MXFP4 的误差全部来自于元素量化这一步：个位数相对误差 25%。它能在低精度下还保得住，是因为这 25% 的误差被**均匀地**施加在"块的量级被正确对齐之后"的数值上。

### 和其他格式横向对比

| 格式 | 元素格式 | 尺度来源 | 块大小 | 元素有效精度 | 尺度开销 | 典型用途 |
| --- | --- | --- | --- | --- | --- | --- |
| **MXFP4** | E2M1（4 bit） | 每块 E8M0 | 32 | 2 bit | 0.25 bit/元素 | 权重低比特量化 |
| **MXFP8** | E4M3 / E5M2（8 bit） | 每块 E8M0 | 32 | 4 bit / 3 bit | 0.25 bit/元素 | 权重 + 激活 |
| **[[learning/precision/02-nvfp4\|NVIDIA FP4]]** | E2M1（4 bit） | 每 16 元素 E4M3 块尺度 + per-tensor FP32 | 16 | 2 bit | 0.5 bit/元素 | （推理）4 bit 权重 |
| [[learning/precision/05-fp8\|fp8]] | E4M3 / E5M2（8 bit） | 每张量标量 | — | 4 bit / 3 bit | 0 | 权重 + 激活 |
| [[learning/precision/09-fp16\|fp16]] | IEEE 半精度（16 bit） | **每个数自带指数** | — | 11 bit | 0 | 通用训练 / 推理 |

对比的核心是**尺度放在哪一级**：

- **fp16 / fp32**：每个数自带指数，动态范围最大、精度最高，但要存 16/32 bit。
- **裸 FP4（无块尺度）**：**一个**尺度管**整个张量**（或每通道）。存储最省（刚好 4 bit），但张量里只要有大动态范围，小值就塌缩。
- **MXFP4**：**一个**尺度管**32 个元素**。尺度开销只有 0.25 bit/元素，却把"谁被压碎"从"整张量"变成了"每个 32 元素块"。

### 什么时候需要它

MXFP4 的价值在于**块级的动态范围自适应**。要看懂它，先看标量 FP4 的死穴。

**标量 FP4 的"表示真空"。** 假设一个权重矩阵，第一块元素幅值在 $10 \sim 20$，第二块元素幅值只有 $0.01 \sim 0.02$。用一个统一尺度（按整个矩阵的最大值来定，把最大幅值对到 6.0），则 $X \approx 4$，此时第二块的最小元素 $0.01$ 远小于最小非零幅值 $0.5 \times X = 2.0$，**全部被压成 0**，这一块的权重信息完全丢失。反过来如果按第二块定尺度，第一块全部削顶。

**MXFP4 怎么救。** 每个 32 元素块**独立**计算自己的尺度，把块内最大幅值刚好对齐到元素格式的最大规范数（6.0）。于是：

- 第一块：$X_1 \approx 4$，各元素落在 ${1.5, 2.0, 3.0, 4.0, 6.0}$ 附近。
- 第二块：$X_2 \approx 0.004$，各元素同样落在同一条离散网格上。

两块**各自用到完整的相对精度**，只是量级差了 1000 倍。这就是"块级动态范围"的意义：**精度是相对的，而范围是逐块给的**（见 OCP MX 规范 §6.3 的转换算法）。

**训练侧的证据。** 在 OCP Microscaling 论文（[arXiv:2310.10537](https://arxiv.org/abs/2310.10537)）里，生成式语言模型用 **MXFP4 权重 + MXFP6 激活/梯度** 从零训练，loss 只比 FP32 略高（GPT-1.5B：2.74 → 2.76），且**不需要改动训练配方**。对推理，**MXFP4 权重配 MXFP8 激活**（混合精度）在 GPT3-175B 上能达到甚至略超 FP32 的基准（ARC easy 0.749 vs 0.744）。

典型场景：

1. **权重的低比特量化（W4A16 / W4A8）**。权重矩阵的每一列（通常是 32 的倍数）内部幅值相对平稳，块尺度正好合适；激活保留在高位格式，避免激活块内宽动态范围被压碎。这是 MXFP4 最主流的用法。
2. **超大 LLM 的显存缩减**。权重压到 4 bit（加上 0.25 bit 尺度 ≈ 4.25 bit），比 fp16 省约 3.7 倍显存，推理吞吐显著提升。
3. **权重 + 激活一起压榨的极限场景**，但此时通常需要配一个更宽的激活格式（MXFP6 / MXFP8）。

### 什么时候不用它

- **直接全量压到 MXFP4（权重 + 激活）做 direct-cast 推理**。论文数据很残酷：MobileNetV2 直接掉到 0.25（崩溃），ResNet-50 从 77.40 掉到 42.39。激活（比如 Softmax 后、残差周围）的**块内**动态范围通常远超 12 倍，会被块尺度压塌。MXFP4 几乎从不单独用于激活。
- **块内动态范围超过 ~12 倍**。一个块的元素幅值如果拉得很开（差一个数量级以上），小元素仍会塌缩到次正规或 0。块尺度只管"块与块之间"，不管"块内部"。
- **需要高精度的数值任务**（病态线性系统、长累加、数值积分）。4 bit 的 $u=25\%$ 让任何 $\kappa u$ 估计都爆炸，这类任务应该去看 [[learning/precision/13-fp64|fp64]] 或 [[learning/precision/15-fp128|fp128]]。
- **没有对应硬件/库支持的算子**。MXFP4 的收益主要在**存储和矩阵乘的吞吐**；如果算子要来回解量化成 FP32 再算，省下的显存被转换开销吃掉，就不划算了。

### 硬件与软件现状

MX 是一个**开放、厂商无关的标准**，这一点从规范作者名单就能看出来：**AMD、Arm、Intel、Meta、Microsoft、NVIDIA、Qualcomm** 共同参与（OCP MX 规范 v1.0，2023 年 9 月）。

- **NVIDIA**：Blackwell 的 tensor core 首次把 4 bit FP4（E2M1，与 MXFP4 同一种元素格式）带进主流 GPU 推理；NVIDIA 在 TensorRT-LLM 中同时暴露 NVIDIA FP4 与基于 OCP 微缩放的方案。要注意 **NVFP4 与 MXFP4 的区别**：元素格式相同，但 NVFP4 用每 16 元素的 E4M3 **块**尺度（另加每 tensor 一个 FP32 二级尺度），MXFP4 用每 32 元素的 **E8M0** 块尺度；NVFP4 的块更小、尺度更细。
- **AMD / Intel / Arm / Qualcomm**：作为规范的共同作者，它们的下一代 AI 加速器把 OCP MX 作为格式选型参考；具体支持程度取决于各自的软件栈。
- **软件仿真**：标准刚出时没有成熟硬件，Microsoft 开源了 [microxcaling](https://github.com/microsoft/microxcaling)，一个基于 PyTorch / CUDA 的 MX 仿真库，用现有 GPU 的 FP 运算模拟块尺度 + 低比特元素，用来复现论文里的精度结果。现在主流推理引擎（TensorRT-LLM、vLLM 等）已逐步接入 MXFP4。

**存储格式 vs 纯计算格式。** MXFP4 本质更像一种**存储 / 权重格式**：训练时保留一份 FP32 主权重，只在**向前/向后传播的矩阵乘**处把权重量化成 MXFP4，矢量算子（LayerNorm、Softmax、残差加）仍用 Bfloat16/FP32，输出回到标量浮点（见论文 §4.1 的计算流）。计算上，因为尺度 $X$ 是 2 的幂，可以**从点积中提出来**，即

$$
\text{Dot}(A,B) = X^{(A)} X^{(B)} \sum_i P_i^{(A)} P_i^{(B)}
$$

每个块的 $X^{(A)} X^{(B)}$ 只在块末乘一次，等于给点积加一个标量乘 / 指数移位，几乎不增加运算量。这也是 MX"效率高"的根本：**块尺度在存储和计算两端的开销都是 O(1) 的**。

### 代码示例

一个纯 Python 的最小实现：把一个块量化成 MXFP4，并展示**标量尺度 vs 块尺度**在"幅值差异大的两块权重"上的差别。

```python
import math

def fp4_magnitudes():
    """E2M1 可表示的幅值集合（先忽略符号）。"""
    mags = [0.0, 0.5]                       # 0 与次正规 M=1 -> 0.5
    for E in (1, 2, 3):                     # 规范数: 2^(E-1) * (1 + M/2)
        for M in (0, 1):
            mags.append(2.0 ** (E - 1) * (1.0 + M / 2.0))
    return sorted(set(mags))

MAGS = fp4_magnitudes()                     # [0, 0.5, 1, 1.5, 2, 3, 4, 6]

def fp4_quant(v):
    """把已按 X 缩放的值 v 量化到 E2M1, 超出上限削顶(保留符号)。"""
    if v == 0:
        return 0.0
    s = 1.0 if v > 0 else -1.0
    a = abs(v)
    q = min(MAGS, key=lambda m: abs(m - a))  # roundTiesToEven 的简化近似
    if a > MAGS[-1]:
        q = MAGS[-1]                         # clamp 到最大规范数 6.0
    return s * q

def block_scale(amax):
    """按 OCP MX 规范 §6.3: X = 2^(floor(log2(amax)) - emax_elem), emax_elem=2。"""
    if amax <= 0:
        return 1.0
    return 2.0 ** (math.floor(math.log2(amax)) - 2)

def mx_quantize(block):
    """把 32 个浮点值量化成 {X, [P_i]}。"""
    x = block_scale(max(abs(v) for v in block))
    return x, [fp4_quant(v / x) for v in block]

def mx_reconstruct(block):
    x, p = mx_quantize(block)
    return [x * q for q in p]

# 两幅值差异 1000 倍的"权重块"(各 32 个元素, 这里简化成 4 个示意)
big   = [15.0, 12.0, 18.0, 11.0] * 8
small = [0.015, 0.012, 0.018, 0.011] * 8
tensor = big + small

# 标量 FP4: 整个张量一个尺度
x_scalar = block_scale(max(abs(v) for v in tensor))
scalar_q = [fp4_quant(v / x_scalar) for v in tensor]
# MXFP4: 每个 32 块一个尺度
mx = mx_reconstruct(big) + mx_reconstruct(small)

def err(orig, quant):
    return max(abs(a - b) / abs(a) for a, b in zip(orig, quant))

print(f"标量尺度 X = {x_scalar:.4f}")
print(f"小块的 4 个元素(标量量化): {[x_scalar*q for q in scalar_q[32:36]]}")
print(f"小块的 4 个元素(MX 量化)  : {mx[32:36]}")
print(f"标量 FP4 最大相对误差 = {err(tensor, scalar_q):.1%}")
print(f"MXFP4  最大相对误差 = {err(tensor, mx):.1%}")
```

运行结果（数值可能因块内具体值而异）：

```
标量尺度 X = 4.0000
小块的 4 个元素(标量量化): [0.0, 0.0, 0.0, 0.0]     # 全部塌缩成 0
小块的 4 个元素(MX 量化)  : [0.015..., 0.012..., ...]  # 完整保留
标量 FP4 最大相对误差 = 100.0%
MXFP4  最大相对误差 = 13.2%
```

关键就是最后两行：**标量尺度把小权重块全部压成 0（相对误差 100%），MXFP4 用逐块尺度把它完整救回来**。4 bit 元素的 25% 舍入误差仍然在，但它被均匀地施加在"块量级正确对齐后"的数值上，不会因为跨块量级差异而放大成灾难性塌缩。

### 一些 tips

1. **MXFP4 主要当"权重格式"用，别当"通用格式"用。** 权和激活一起压到 4 bit 的 direct-cast 推理在论文里几乎全线崩溃；实战是 W4A16 / W4A8（权重 MXFP4 + 激活高位）。
2. **块内动态范围上限约 12 倍。** 块尺度管"块与块"，不管块内。一个块的元素幅值一旦拉开一个多数量级，小元素仍会被压到 0，所以 MXFP4 适合"块内幅值平稳"的数据（权重矩阵的一列），不适合激活。
3. **把块对到 32 的倍数，并沿"归约维度"做。** 尺度通常沿矩阵乘的归约维（一行或一列）共享；注意**转置和量化不可交换**：重量化了再转置，得另存一份转置后的权重。
4. **训练时保留 FP32 主权重。** MXFP4 只出现在矩阵乘处的量化，矢量算子（Softmax、LayerNorm、残差）留在 Bfloat16 / FP32，输出回标量浮点；每一步用 FP32 主权重更新。
5. **$u=25\%$ 是常态，不是 bug。** 单元素只有约 0.6 位十进制精度；它的价值在于**显存省 3.7 倍 + 矩阵乘吞吐**，而不是数值精确。需要精确就上 MXFP8（$u=2^{-4}$）或 fp16。
