> fp16（IEEE 754 binary16）用 5 位指数和 10 位尾数，把 fp32 的"宽范围"砍掉，只保留一块**精度尚可、但范围极窄**的数轴。它适合"数值都落在 $[2^{-14}, 2^{15}]$ 附近、且愿意在零点附近做 loss scaling 兜底"的场景。这正是训练初期梯度动不动就跑到 $10^{-6}$ 以下、又需要 2 倍速度时的标准答案。

### 位布局

binary16 是 IEEE 754-2008 正式规范中的一员（之前叫 half precision），字段安排如下：

| 字段 | 位数 |
| --- | --- |
| sign | 1 |
| exponent | 5（偏置 15） |
| fraction | 10 |
| 总计 | 16 |

普通数（指数域 $E \in [1, 30]$）的表示和 fp32 完全同构，只是指数和尾数都变短：

$$
x = (-1)^s \cdot 2^{E - 15} \cdot (1.f)_2
$$

当指数域 $E = 0$（次正规数）时，前导 1 被隐去，表示改为

$$
x = (-1)^s \cdot 2^{-14} \cdot (0.f)_2
$$

当 $E = 31$：尾数全 0 为 $\pm\infty$，尾数非 0 为 NaN。对照 fp32 的偏置 127，fp16 的指数窗口只覆盖 $2^{-14}$ 到 $2^{15}$。这就是它范围小的根源。

### 关键数值

- **有效精度**：11 bit（10 位尾数 + 隐式前导 1），换算成十进制约 $11 \log_{10} 2 \approx 3.3$ 位。
- **单位舍入**：$u = 2^{-11} = 1/2048 \approx 4.88 \times 10^{-4}$。这是相对误差的下限；fp32 的 $2^{-24} \approx 5.96 \times 10^{-8}$ 在它面前差 4 个数量级。
- **溢出上限**：最大正规数 $(2 - 2^{-10}) \cdot 2^{15} = 65504$，超过即变成 inf。
- **下溢下限**：最小正规数 $2^{-14} \approx 6.10 \times 10^{-5}$；更小进入次正规区，最小次正规数 $2^{-24} \approx 5.96 \times 10^{-8}$。

| 格式 | 指数位 | 尾数位（含隐式） | 十进制有效位 | 单位舍入 | 最大量级 |
| --- | --- | --- | --- | --- | --- |
| **fp16** | **5** | **11** | **≈3.3** | $2^{-11} \approx 4.88e-4$ | $6.55 \times 10^{4}$ |
| bf16 | 8 | 8 | ≈2.4 | $2^{-8} \approx 3.91e-3$ | $3.39 \times 10^{38}$ |
| fp32 | 8 | 24 | ≈7.2 | $2^{-24} \approx 5.96e-8$ | $3.40 \times 10^{38}$ |

把 fp16 的 5 位指数和 10 位尾数放在数轴上，能直接看到它的"两头受气"：既没有 bf16 那种接近 fp32 的大范围，又没有 fp32 的精度：

```
2^-24  次小      2^-14        1       2^15 = 32768    65504
 |----------|----|----|------------|------------|--|
   次正规区   最小正规数       数轴只能覆盖到这里 ──> 再大就得指数上溢出
```

### fp16 vs bf16 vs fp32：同一字节数，三种取舍

三者都占用 16 位（bf16 / fp32 除指数外），但把"精度"和"范围"按不同权重分配：

| 特性 | fp16 | bf16 | fp32 |
| --- | --- | --- | --- |
| 总位数 | 16 | 16 | 32 |
| 指数位 | 5 | 8 | 8 |
| 尾数位（含隐式） | 11 | 8 | 24 |
| 十进制有效位 | ≈3.3 | ≈2.4 | ≈7.2 |
| 单位舍入 | $2^{-11}$ | $2^{-8}$ | $2^{-24}$ |
| 最大表示 | 65504 | $3.39 \times 10^{38}$ | $3.40 \times 10^{38}$ |
| 最小正规数 | $6.10 \times 10^{-5}$ | $1.18 \times 10^{-38}$ | $1.18 \times 10^{-38}$ |
| 典型用途 | 混合精度训练 | 迁移/推理、对范围敏感 | 基准精度、主权重 |

**fp16 用范围换精度，bf16 用精度换范围**。bf16 不担心梯度下溢，但只能保住约 2.4 位十进制；fp16 在 $[6 \times 10^{-5}, 65504]$ 内比 bf16 精确约 8 倍（$2^{-11}$ vs $2^{-8}$），可一旦出了这个窗口就崩。这也是两者在训练脚本里身份不同的原因。

### 什么时候需要它

fp16 的黄金场景是 **GPU 上的混合精度训练（mixed precision training）**，它是"想省显存、想翻倍吞吐，又不想彻底放弃精度"时的默认答案：

1. **Tensor Core 加速**。NVIDIA 的 tensor core 对 fp16 乘加提供约 fp32 两倍的 throughput，且 **fp16 相乘、fp32 累加**（accumulate 在 fp32 里），把舍入误差限制在乘积阶段而不是累加阶段，精度损失比想象中小。

2. **减半的显存与带宽**。激活值、梯度以 fp16 存储，直接省一半显存和一半通信量，能塞更大的 batch、更大的模型。

3. **配合 FP32 主权重 + 动态 loss scaling**。标准的混合精度配方：
   - 用 fp16 存**激活值和梯度**，算**前向+反向**；
   - 用 fp32 存**主权重、优化器状态**（master weights），更新步照常算 fp32；
   - 由于梯度常常远小于 $2^{-14}$（最小正规数），直接存 fp16 会下溢成 0 或次正规数、丢精度，所以**在反向前把 loss 乘上一个比例因子 $\mathcal{S}$**，梯度随之放大到可用区间，反向结束再除以 $\mathcal{S}$ 还原。$\mathcal{S}$ 从 $2^{11}$ 附近起步、按梯度是否溢出动态调节。这就是**动态 loss scaling**。

当模型权重、中间值都落在 fp16 的窄范围内时，这套组合是速度和精度的最佳平衡点。**什么时候不用**：需求超出 $[2^{-24}, 65504]$ 范围（比如某些归一化统计量、大 logits），或对精度要求高于约 3.3 位十进制的场景（科学计算、收敛敏感的训练），就该退回 bf16 / fp32 / fp64。

### 硬件和软件现状

- **GPU**：CUDA 从 `compute capability 5.3` 起支持 `__half` 类型，tensor core（Volta 及以后）原生做 fp16×fp16→fp32 的混合精 度乘加。PyTorch / TensorFlow 的 AMP（自动混合精度）对 fp16 + loss scaling 有现成封装。
- **CPU**：x86-64 的 AVX-512 FP16（Sapphire Rapids 起）支持硬件 fp16；更早的 CPU 上 GCC/Clang 用 `_Float16` 会退化为软件模拟。ARM 的 `__fp16` 在部分核上原生，另有 NEON FP16 指令。
- **存储 vs 计算**：关键区别是 **fp16 常作为"存储格式"而不是"计算格式"**。推理时把权重量化成 fp16 省带宽，矩阵乘仍走 fp32 累加；bf16 则更常被当作"计算即存储"的替代。真正"只用 fp16 做完整计算"的场合多在移动端 / 边缘推理。

### 代码示例

Python + NumPy 可以直接演示 fp16 的**范围**和**精度**。溢出、下溢、以及加法不精确很直观：

```python
import numpy as np
f16 = np.float16

# 1) 溢出上限：超过 65504 就变 inf
print("max fp16      =", f16(65504))
print("65504 * 2     =", f16(65504) * f16(2))   # inf（溢出）

# 2) 下溢：低于最小次正规数 2^-24 直接塌缩成 0
print("2^-24（次小） =", f16(2**-24))            # 5.96e-08
print("2^-25         =", f16(2**-25))            # 0.0（下溢）
print("2^-14（最小正规数）=", f16(2**-14))        # 6.10e-05

# 3) 精度：在 1.0 附近，间距只有 2^-10，½ 个间距之下的数被舍掉
print("1 + 2^-10     =", f16(1) + f16(2**-10))   # 1.001（下一个可表示数）
print("1 + 2^-11     =", f16(1) + f16(2**-11))   # 1.0 （恰为半个间距，向偶数舍入 → 1.0）
print("50000 + 1     =", f16(50000) + f16(1))    # 50000（此时间距已大到 32）

# 4) 累加误差：0.1 + 0.2 在 fp16 里不是 0.3
print("0.1 + 0.2     =", repr(f16(0.1) + f16(0.2)))   # 0.2998（≠ 0.3）
```

把第 3、4 条放到训练视角：梯度如果落在 $10^{-6}$，无法用 fp16 直接表示（下溢成 0），这就是必须做 **loss scaling** 的原因：先乘一个比例因子把梯度抬到可用区间，更新完再除回去。

若在 CUDA 里做混合精度的核心乘加，注意用 `__half`：

```cpp
#include <cuda_fp16.h>

__half a = __float2half(1.5f);
__half b = __float2half(2.0f);

// 元素级指令：__hmul / __hfma 都在 half 里算，累加也停在 half（精度受限）
__half p = __hmul(a, b);

// 要"fp16 相乘、fp32 累加"，得走 tensor core 的 wmma / mma 路径，
// 显式指定 float 累加器（accumulator）——这才是混合精度"混合"的含义。
float acc = __half2float(a) * __half2float(b);   // 示意：转回 float 再乘加
```

实战中不要让整条链都停在 fp16。**主权重、优化器状态留在 fp32**，只有激活和梯度走 fp16，再配合动态 loss scaling，才是混合精度训练的完整配方。

### 一些 tips

1. **记住窗口**：fp16 只在 $[2^{-24}, 65504]$ 内"安全"。统计量、归一化参数、大的 logits 这类容易越界的量，留在 fp32。
2. **loss scaling 是刚需**。梯度低于 $2^{-14}$ 时，不缩放就直接下溢成 0，训练会停止；动态缩放（每步根据是否出现 inf/NaN 调整 $\mathcal{S}$）比固定缩放更省心。
3. **主权重必须 fp32**。只在正向/反向用 fp16，权重更新用 fp32，否则权重本身的舍入就毁了训练。这也是混合精度所谓"混合"的含义。
4. **留意 FTZ（flush-to-zero）**：部分实现把次正规数刷成 0，导致本该是次正规数的小梯度直接消失，对训练有影响。开启是否合理要看硬件和库的行为。
5. **精度不够就换 bf16，而不是直接上 fp32**。bf16 用同样的 16 位换到 fp32 的指数范围，省掉了 loss scaling 的复杂度，代价是精度略低；对范围敏感的模型 bf16 往往比 fp16 省心。
