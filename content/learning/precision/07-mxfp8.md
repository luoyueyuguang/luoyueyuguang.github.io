聊 FP8，大家第一反应是"每 8 bit 装一个数，误差百分之几"。但真正让 FP8 **能用于训练**的，往往不是元素格式本身，而是**谁负责缩放**。[[learning/precision/05-fp8|FP8]] 用**一个** per-tensor 尺度去撑动态范围，可一旦权重/激活的量级在张量内部剧烈起伏，这个"单一尺度"就把小值压碎。**MXFP8（OCP 微缩放，Microscaling / MX）**给出了另一条路：不再是整个张量一个尺度，而是**每 32 个 8 bit 元素共享一个 8 bit 块尺度**。它是 OCP（Open Compute Project）在 2023 年 9 月发布、AMD / Arm / Intel / Meta / Microsoft / NVIDIA / Qualcomm 联合制定的 MX 格式家族里"8 bit 元素"的那一个，在 [[learning/precision/01-overview|精度总览]] 的"低精度 AI 格式"谱系里，和 [[learning/precision/03-mxfp4|MXFP4]] 只差元素位宽。

一句话给直觉：

> MXFP8 不是给每个数配一个指数，而是**每 32 个数配一个共享的 2 的幂指数**。这个共享指数（E8M0）本身不含精度、只给块"定位置"，于是 32 个元素的相对精度（E4M3 的 $u=2^{-4}$）完全由元素格式决定，而**块与块之间**的量级可以差上几百个数量级也不相互污染。它解决的是**标量 FP8 在权重幅值剧烈变化时的"表示真空"**——一个尺度管全张量，小权重块会被压成 0；MX 的块尺度让每一块"各取所需"，这才让 FP8 在训练里站得住。

相关：[[learning/precision/05-fp8|FP8]]（标量/每张量尺度）、[[learning/precision/03-mxfp4|MXFP4]]（同一套块尺度，4 bit 元素）、[[learning/precision/09-fp16|FP16]]（每个数自带指数的大范围格式）、[[learning/precision/01-overview|精度总览]]。

### 位布局

一个 MXFP8 块由**一个共享尺度 $X$** + **$k = 32$ 个元素 $P_i$** 组成。尺度与元素的类型独立选择，物理内存中不强制连续——尺度可以和元素挨着放，也可以单独存（见 OCP MX 规范 §5.1）。

```
  块尺度 X (E8M0, 8 bit)           32 个元素 P_i (E4M3 或 E5M2, 每 8 bit)
  +-----------+                 +--------+--------+-----+--------+
  |  exponent |                 | s|E|M | s|E|M | ... | s|E|M |
  +-----------+                 +--------+--------+-----+--------+
   bias = 127                      1+4+3 (E4M3)       1+5+2 (E5M2)
   X = 2^(E - 127)                 每元素 8 bit
```

存储一个块需要 $w + kd = 8 + 32 \times 8 = 264$ bit，平均每个元素 $264/32 = 8.25$ bit——比裸的 8 bit 只多了 $8/32 = 0.25$ bit 的"管理费"。这 0.25 bit/元素就是"块级动态范围"的全部代价。

**块尺度 $X$：E8M0。** 一个**无符号的、带偏置的 Float32 指数**——没有符号、没有尾数，bias = 127：

$$
X = 2^{E - 127}
$$

$E$ 是 8 bit 无符号值，合法范围 $E = 0 \ldots 254$，对应指数 $-127 \sim 127$（$E=255$ 被保留为唯一的 NaN 编码 $11111111_2$）。注意 E8M0 **不含 Inf**——它只描述一块的"量级"，不能描述无穷。关键点是：**E8M0 本身不贡献精度，只贡献范围**，而且它的覆盖范围（$2^{-127} \sim 2^{127}$）比 Float32 的指数范围还宽，所以在现实数值范围内，块尺度永远不会成为溢出的瓶颈。由于 $X$ 永远是**精确的 2 的幂**，缩放本身不引入任何舍入误差——MXFP8 的全部误差都来自元素量化这一步。

**元素 $P_i$：E4M3 或 E5M2。** 就是 [[learning/precision/05-fp8|FP8]] 里那两种标准 8 bit 浮点，各自带自己的偏置（E4M3 bias 7，E5M2 bias 15），隐式前导 1：

$$
P = (-1)^s \cdot 2^{E - \text{bias}} \cdot (1.M)_2
$$

整个块的值是 $v_i = X \cdot P_i$（若 $X$ 为 NaN，则整块都为 NaN）。因为 $X$ 是 2 的幂，$v_i = X \cdot P_i$ 等价于把 $P_i$ 的指数**平移**一个固定的量——这就是"块尺度"的直觉：同一块里的所有元素一起左右移动，移动的位数由 $X$ 决定。

块尺度的计算（OCP MX 规范 §6.3），取块内最大绝对值 $a_{\max}$：

$$
X = 2^{\lfloor \log_2 a_{\max} \rfloor - \text{emax}_\text{elem}}
$$

其中 $\text{emax}_\text{elem}$ 是元素格式的**最大正规指数**：E4M3 对应 $448 = 2^8 \times 1.75$，所以 $\text{emax}_\text{elem} = 8$；E5M2 对应 $57344 = 2^{15} \times 1.75$，所以 $\text{emax}_\text{elem} = 15$。除以 $X$ 后，块内最大元素被拉到"刚好在元素格式顶端附近"，小值也跟着被抬高到可表示范围内——这才是不让它们塌缩的关键。

### 关键数值

| 参数 | E4M3 版本 | E5M2 版本 |
| --- | --- | --- |
| 元素格式 | E4M3（1 符号 + 4 指数 + 3 尾数） | E5M2（1 符号 + 5 指数 + 2 尾数） |
| 块大小 $k$ | $32$ | $32$ |
| 块尺度格式 | E8M0（8 bit 带偏置指数，bias 127） | 同左 |
| 尺度覆盖范围 | $2^{-127} \sim 2^{127}$ | 同左 |
| 元素有效精度 $p$ | **4 bit**（1 隐式前导 + 3 显式尾数） | **3 bit**（1 隐式前导 + 2 显式尾数） |
| 元素单位舍入 $u = 2^{-p}$ | $2^{-4} = 0.0625$ | $2^{-3} = 0.125$ |
| 十进制有效位数 | $\approx 4\log_{10}2 \approx 1.20$ | $\approx 3\log_{10}2 \approx 0.90$ |
| 元素最大有限值 | $448$ | $57344$ |
| 元素最小正规数 | $2^{-6} \approx 0.015625$ | $2^{-14} \approx 6.10 \times 10^{-5}$ |
| 元素最小非零（次正规） | $2^{-9} \approx 0.001953$ | $2^{-16} \approx 1.53 \times 10^{-5}$ |
| 块内动态范围（最大/最小非零） | $448 / 2^{-9} \approx 2.3 \times 10^5$（约 5.4 个数量级） | $57344 / 2^{-16} \approx 3.8 \times 10^9$（约 9.6 个数量级） |
| 每块位数 | $8 + 32 \times 8 = 264$ bit | 同左 |
| 平均每元素位宽 | $8.25$ bit | 同左 |
| 块尺度开销 | $8/32 = 0.25$ bit/元素 | 同左 |
| Infinity（元素） | **无**（仅 NaN） | **有** |

两个要特别理解的点：

- **$u$ 和标量 FP8 完全一样**。MXFP8 的"单元素精度"并没有因为加了块尺度而改变——E4M3 仍是 $u=2^{-4}=6.25\%$，E5M2 仍是一档 12.5%。块尺度不增加精度，它只**保证每一块的量级被正确对齐**，让元素格式的精度能真正用得上。
- **$X$ 是 2 的幂，本身无误差**。所以 MXFP8 的误差全部来自元素量化。它能在低精度下还保得住，不是因为每个数更准，而是因为这 $6.25\%$ 的误差被**均匀地**施加在"块量级对齐之后"的数值上，不会被跨块的量级差异放大成灾难性塌缩。

### 和其他格式横向对比

| 格式 | 元素格式 | 尺度来源 | 块大小 | 元素有效精度 | 尺度开销 | 典型用途 |
| --- | --- | --- | --- | --- | --- | --- |
| **MXFP8** | E4M3 / E5M2（8 bit） | 每块 E8M0 | 32 | 4 bit / 3 bit | 0.25 bit/元素 | 权重 + 激活（训练/推理） |
| **[[learning/precision/05-fp8\|FP8]]** | E4M3 / E5M2（8 bit） | 每张量标量 | — | 4 bit / 3 bit | 0 | 权重 + 激活（单尺度） |
| **[[learning/precision/03-mxfp4\|MXFP4]]** | E2M1（4 bit） | 每块 E8M0 | 32 | 2 bit | 0.25 bit/元素 | 权重低比特量化 |
| [[learning/precision/06-nvfp8\|NVFP8]] | E4M3 / E5M2（8 bit） | 每通道/张量标量（硬件变体） | — | 4 bit / 3 bit | 0 | 推理 W8A8 |
| [[learning/precision/09-fp16\|fp16]] | IEEE 半精度（16 bit） | **每个数自带指数** | — | 11 bit | 0 | 通用训练 / 推理 |

对比的核心不是"谁 bit 数更少"，而是**尺度放在哪一级**：

- **fp16 / fp32**：每个数自带指数，动态范围最大、精度最高，但要存 16/32 bit。
- **标量 FP8 / NVFP8**：**一个**尺度管**整个张量**（或每通道）。存储正好压到 8 bit，但张量里只要有大动态范围，小值就塌缩。
- **MXFP8**：**一个**尺度管**32 个元素**。尺度开销只有 0.25 bit/元素，却把"谁被压碎"从"整张量"压实成"每个 32 元素块"。

两种"FP8"的元素格式完全一样，但**尺度粒度**是分水岭：标量 FP8 是"一整个张量共用一个量级"，MXFP8 是"每 32 个数各有一个量级"。同样是 $u=6.25\%$，前者可能让一根权重列（幅值从 $10^{-3}$ 到 $10^2$）的小端全部归零，后者让每一列都保得住。

### 什么时候需要它

MXFP8 的价值不在"8 bit 能存多细的数"，而在**块级的动态范围自适应**。要看懂它，先看标量 FP8 的死穴。

**标量 FP8 的"表示真空"。** 假设一个权重矩阵，第一列元素幅值在 $100 \sim 200$，第二列只有 $3 \times 10^{-4}$ 量级。用一个统一的尺度（按整矩阵最大值定，把最大幅值对齐到元素格式顶端），则第一列刚好，第二列的最小元素 $3 \times 10^{-4}$ 会被压到元素格式的最小非零 $2^{-9} \approx 0.002$ 之下，**全部塌缩成 0**——这一列的权重信息完全丢失。反过来按第二列定尺度，第一列全部削顶。

**MXFP8 怎么救。** 每个 32 元素块**独立**算自己的尺度，把块内最大值刚好对齐到元素格式顶端，于是：

- 第一列：$X_1 \approx 2^{7-8} = 0.5$，各元素落在 E4M3 的高位网格上。
- 第二列：$X_2 \approx 2^{-11-8} = 2^{-19}$，各元素**同样**落在 E4M3 的高位网格上。

两列各自用到完整的 $u=6.25\%$ 相对精度，只是量级差了 $10^5$ 倍。这就是"块级动态范围"的意义：**精度是相对的，而范围是逐块给的**。

**训练侧的证据。** 在 OCP Microscaling 论文（[arXiv:2310.10537](https://arxiv.org/abs/2310.10537)）里，用 **MXFP8 权重 + 激活**训练的生成式语言模型从零训练，loss 与 FP32 / bfloat16 基准几乎持平，且**不需要改动训练配方**；相比之下标量 FP8（单尺度）在同样任务上掉得更厉害。这正是"块尺度让 FP8 能用"的直接证据。

典型场景：

1. **权重 + 激活一起压到 8 bit 的混合精度训练**（前向 E4M3，梯度 E5M2）。这是 MXFP8 相比 MXFP4 的关键优势：8 bit 元素的块内动态范围能容纳激活值的起伏，而不像 4 bit 那样一块就塌。
2. **权重 + 激活的 W8A8 推理**，且希望比单尺度 FP8 更稳（比如权重列与激活列量级差异大时，块尺度能保住小值）。
3. **大模型推理的显存/带宽缩减**。8 bit（外加 0.25 bit 尺度 ≈ 8.25 bit/元素），相比 fp16 减半，吞吐显著提升。
4. **MXFP4 的"激活侧搭档"**。论文里常见的组合是 **MXFP4 权重 + MXFP8 激活**——权重压到 4 bit，激活用 8 bit 块尺度兜住更宽的动态范围。

### 什么时候不用它

- **需要超过约 1–2 位十进制有效数字的数值任务**（病态线性系统、长累加、数值积分）。MXFP8 的元素误差仍是百分之几量级，$\kappa u$ 会爆炸；这类任务去 [[learning/precision/13-fp64|fp64]] 或 [[learning/precision/15-fp128|fp128]]。
- **块内动态范围超过元素格式的上限**。一个块的元素幅值如果拉得比 E4M3 的约 5.4 个数量级还开，小元素仍会塌缩到次正规或 0。块尺度只管"块与块之间"，不管"块内部"。
- **没有对应硬件/库支持的算子**。MXFP8 的收益主要在**存储和矩阵乘吞吐**；如果算子要来回解量化成 FP32 再算，省下的带宽被转换开销吃掉，就不划算。
- **激活值可能超过 E4M3 的 448 且不能接受饱和**。指数很大的激活（Softmax 前、残差周围）用 E5M2（能到 57344、且有 inf）比 E4M3（无 inf、只饱和到 448）更安全——这和 [[learning/precision/05-fp8|FP8]] 的取舍一样。

### 硬件与软件现状

MX 是一个**开放、厂商无关的标准**，不是某个厂商的私有格式——规范作者名单是 **AMD、Arm、Intel、Meta、Microsoft、NVIDIA、Qualcomm**（OCP MX 规范 v1.0，2023 年 9 月）。

- **元素格式已就绪**：MXFP8 的元素（E4M3 / E5M2）正是 NVIDIA / OCP FP8 张量核使用的标准 8 bit 浮点。也就是说，**硬件层面的元素乘法已有原生支持**；MX 加上的是"块尺度"这一层包装。
- **软件仿真**：标准刚出时没有配套硬件，Microsoft 开源了 [microxcaling](https://github.com/microsoft/microxcaling)——一个基于 PyTorch / CUDA 的 MX 仿真库，用现有 GPU 的 FP 运算模拟"块尺度 + 低比特元素"，用来复现论文里的精度结果。它也是目前理解/应用 MX 格式最直接的参考实现。
- **落地程度**：MX 作为开放标准，逐步进入各厂商的推理/训练栈（TensorRT-LLM、vLLM 等）。具体到某一款硬件是否原生执行"块尺度 + FP8 元素"的打包计算，取决于各自的产品路线，不应一概而论——**想确认某平台是否真正支持，查它的 MX 相关文档，而不是把它当成标准 FP8**。

**存储格式 vs 纯计算格式。** MXFP8 更像一种**存储 / 权重格式**：训练时保留一份 FP32 主权重，只在**向前/向后传播的矩阵乘**处把权重量化成 MXFP8，矢量算子（LayerNorm、Softmax、残差加）仍用 Bfloat16 / FP32，输出回到标量浮点。计算上，因为尺度 $X$ 是 2 的幂，可以从点积里**提出来**：

$$
\text{Dot}(A,B) = X^{(A)} X^{(B)} \sum_i P_i^{(A)} P_i^{(B)}
$$

每个块的 $X^{(A)} X^{(B)}$ 只在块末乘一次，等价于给点积加一个指数移位，几乎不增加运算量。所以块尺度在**存储和计算两端的开销都是 O(1)**——这正是 MX"效率高"的根本。

### 代码示例

下面用纯 Python 实现一个最小块量化 / 解量化，对比**标量 FP8（整张量一个尺度）** 与 **MXFP8（每 32 块一个尺度）** 在一段"两列幅值相差 $10^5$ 倍"的权重上的差别。

```python
import math

# 元素格式参数（microxcaling / OCP MX 确认）：
#   E4M3: 4 exp(bias 7) + 3 mantissa, max=448,  emax=8,  最小非零=2^-9
#   E5M2: 5 exp(bias 15) + 2 mantissa, max=57344, emax=15, 最小非零=2^-16
E4M3 = dict(mant=3, maxv=448.0,   emax=8,  minv=2.0 ** -9)
E5M2 = dict(mant=2, maxv=57344.0, emax=15, minv=2.0 ** -16)

def quant_elem(x, fmt):
    """把已按 X 归一化的值量化到元素格式网格，超上限饱和、不够最小非零归零。"""
    if x == 0:
        return 0.0
    s = 1.0 if x > 0 else -1.0
    a = abs(x)
    if a < fmt["minv"]:              # 小于最小非零(次正规之下) -> 0
        return 0.0
    a = min(a, fmt["maxv"])          # MX 转换用 clamp，不用 inf
    e = math.floor(math.log2(a))     # 当前数量级
    grid = 2.0 ** (e - fmt["mant"])  # 该指数下可表示值的间隔
    q = round(a / grid) * grid       # 四舍五入到最近网格点
    return s * min(q, fmt["maxv"])

def block_scale(amax, emax):
    """X = 2^(floor(log2(amax)) - emax)，精确的 2 的幂。"""
    if amax <= 0:
        return 1.0
    return 2.0 ** (math.floor(math.log2(amax)) - emax)

def mx_quantize(block, fmt):
    """把 32 个浮点值量化成 {X, [P_i]}。"""
    X = block_scale(max(abs(v) for v in block), fmt["emax"])
    return X, [quant_elem(v / X, fmt) for v in block]

def mx_reconstruct(block, fmt):
    X, p = mx_quantize(block, fmt)
    return [X * q for q in p]

fmt = E4M3
big   = [200.0, 150.0, 180.0, 120.0] * 8     # 块 1: 量级 ~200 (32 个元素)
small = [5e-4,  4e-4,  6e-4,  3e-4]  * 8     # 块 2: 量级 ~5e-4 (32 个元素)
tensor = big + small                          # 两个 32 元素块

# 标量 FP8: 整个张量一个尺度
X_scalar = block_scale(max(abs(v) for v in tensor), fmt["emax"])
scalar_q = [quant_elem(v / X_scalar, fmt) * X_scalar for v in tensor]

# MXFP8: 每 32 块一个尺度
mx = mx_reconstruct(big, fmt) + mx_reconstruct(small, fmt)

def relerr(orig, quant):
    return max(abs(a - b) / abs(a) for a, b in zip(orig, quant))

print(f"标量尺度 X = {X_scalar:.4f}")
print(f"小块前 4 个元素(标量) : {[round(v,6) for v in scalar_q[32:36]]}")
print(f"小块前 4 个元素(MX)   : {[round(v,6) for v in mx[32:36]]}")
print(f"标量 FP8 最大相对误差 = {relerr(tensor, scalar_q):.1%}")
print(f"MXFP8   最大相对误差 = {relerr(tensor, mx):.1%}")
```

运行结果：

```text
标量尺度 X = 0.5000
小块前 4 个元素(标量) : [0.0, 0.0, 0.0, 0.0]      # 全部塌缩成 0
小块前 4 个元素(MX)   : [0.000488, 0.000397, 0.00061, 0.000305]   # 完整保留
标量 FP8 最大相对误差 = 100.0%
MXFP8   最大相对误差 = 4.0%
```

关键就是最后两行：**标量尺度把 $5\times10^{-4}$ 的那一块全部压成 0（相对误差 100%），MXFP8 用逐块尺度把它完整救回来**。8 bit 元素的 $6.25\%$ 舍入误差仍然在，但它被均匀地施加在"块量级正确对齐后"的数值上，不会因为跨块量级差异而放大成灾难性塌缩。

### 一些 tips

1. **MXFP8 的 $u$ 和标量 FP8 一模一样，别把它当"更精"的 FP8。** 它只是把"尺度放在哪一级"改善了；单元素仍然是 1.2 位十进制。它的价值是**块级动态范围 + 每元素只有 0.25 bit 管理费**，不是数值精确。
2. **块内动态范围上限约 5.4（E4M3）/ 9.6（E5M2）个数量级。** 块尺度管"块与块"，不管块内。一个块的元素幅值一旦拉得更开，小元素仍会被压到 0——所以 MXFP8 适合"块内幅值平稳"的数据。权重矩阵沿归约维（一行或一列）通常满足这一点。
3. **训练时前向用 E4M3、梯度用 E5M2。** 和标量 FP8 一样的取舍：前向无 inf、饱和到 448 更稳；梯度的动态范围更"没谱"，E5M2 的 57344 上限和有 inf 更安全。两者**不能直接相加**——bias 和网格不同，要各自带尺度换算成 fp32 再更新。
4. **训练时保留 FP32 主权重。** MXFP8 只出现在矩阵乘处的量化，矢量算子（Softmax、LayerNorm、残差）留在 Bfloat16 / FP32，输出回标量浮点；每一步用 FP32 主权重更新。
5. **块大小必须是 32 的倍数，且要沿归约维做。** 这是 OCP MX 的硬约束；注意**转置和量化不可交换**——重量化后再转置，得另存一份转置后的权重，否则块尺度会跨错维度。
